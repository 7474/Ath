# アーヴ語翻訳のアーキテクチャ

この文書は、`baronh` パッケージと `web/` の翻訳・音声が、何を保証し何を捨てているかを記録する。規則ベースは CLI とブラウザで同じ方針である。生成翻訳の本線は **サーバサイドのエージェント**（`POST /api/translate`）であり、辞書はプロセス内の簡易ベクトル索引、文法はシステムプロンプトに全文を載せる。ブラウザから Chat Completions を単発で叩く経路は実験用に残す。

公式の完全辞書は公開されていない。文法の骨格は Wikipedia「[アーヴ語](https://ja.wikipedia.org/wiki/%E3%82%A2%E3%83%BC%E3%83%B4%E8%AA%9E)」（CC BY-SA）、語彙はファンによる再構成を走査した二次資料である。訳は再構成であり誤りを含む。

## 目的

- 規則ベースはローカル完結。辞書と文法規則だけで ja / en / baronh を翻訳し、読み上げまで行う。Web ではアーヴ語を選んだ入出力欄だけアース文字フォントで表示する。ローカル辞書モードでは、未登録語をベクトル検索で寄せるかどうかを選べる（既定はオフ）。
- 他言語 → アーヴ語では、辞書に無い普通名詞を造語せず、**ベクトル検索と語釈の類義語で意味が通るように寄せる**。
- サーバエージェントは生成 AI が必須。モデルが辞書をベクトル検索し、文法コンテキストのうえで文を組む。ブラウザからの単発呼び出しには限界がある（キー露出、CORS、往復回数）。ページ上のベクトル索引は GitHub Actions が事前構築した成果物を読む。
- 辞書全文は 1 回の API 呼び出しに載せない。文法の骨格はエージェントのシステムプロンプトに載せる。
- モデルが造語した普通名詞を、そのままアーヴ語として出さない。

## 全体構成

```
入力（ja / en / baronh）
        │
        ▼
  規則ベース翻訳（辞書 lookup + 格変化 / 動詞活用）
        │
        ├── --engine local / Web の「ローカル辞書」: この訳を採用
        ├── --engine agent / Web の「サーバエージェント」
        │      ① 原文トークンを簡易ベクトル索引で検索し、文法全文をシステムプロンプトへ
        │      ② 生成 AI が search_lexicon 等を queries 一括で 1 往復
        │      ③ 文の組み立てはモデル。規則下訳は渡さない
        │      ④ 生成したアーヴ語を辞書語形と照合。造語なら再生成（規則下訳には戻さない）
        └── --engine openai / Web の「生成AI（ブラウザ）」
               クライアントが Chat Completions を直接呼ぶ実験経路
        │
        ▼
  Ath キーと仮名読みは翻訳エンジン側で再計算
        │
        ▼
  読み上げ（別経路。翻訳 API は音声を返さない）
```

実装の対応は次のとおり。

| 役割 | Python | ブラウザ |
|---|---|---|
| 規則翻訳 | `baronh/translate.py` | `web/js/engine.js` の `translate` |
| 辞書・点数付け | `baronh/lexicon.py` | 同ファイルの `Lexicon.rank` / `search` |
| 類義語寄せ | `baronh/synonyms.py` | `web/js/engine.js` の `findSynonyms` |
| 簡易ベクトル索引 | `baronh/vectordb.py` | `web/js/vectordb.js`（Flat 索引） |
| 文法コンテキスト | `baronh/grammar.py` の `grammar_context()` | `web/js/engine.js` の `grammarContext()` |
| サーバエージェント | `baronh/agent.py` + `baronh/server.py` | `web/js/app.js` が `POST /api/translate` |
| 生成 AI ハーネス | `baronh/agent.py` | `web/js/engine.js` の `translateAgent` |
| 格・活用 | `baronh/grammar.py` | `web/js/engine.js` |
| 発音転記・読み | `baronh/phonology.py` | `web/js/engine.js` |

クラウドへの載せ方（Cloud Run + Vertex、Bedrock AgentCore など）は [DEPLOY.md](DEPLOY.md) を参照する。

## 言語パック（架空言語の設計と、実在言語への寄せ方）

アーヴ語の規則は `grammar.py` / `phonology.py` に固定されている。これを一般化したものが `langs/` の言語パックである。詳細は [langs/README.md](../langs/README.md)。

- 新規言語は `python -m baronh init-lang <id>` で `langs/mina` を複製し、音韻・形態・統語・辞書を書く。
- 実行は `baronh/transfer.py`（転移翻訳）、`baronh/g2p.py`（仮名・IPA）、`baronh/asr.py`（語形制約の認識）。
- アーヴ語の本番翻訳は従来エンジンのまま。`langs/baronh/` は記述と読み・認識の委譲用である。
- 実在言語へ近づけるときは、解析と音響だけ既存モデルに差し、語彙と形態の制約はパックに残す。

## 規則ベース（既定）

辞書見出しと日本語・英語語釈の照合、7 格、動詞活用、主題 `F'a`、疑問の `sa` などを規則で組む。生成 AI がオフでもこれが最終訳になる。

辞書にないカタカナ名・欧文の固有名詞は、日本語ローマ字ではなくアーヴ語の正書法へ発音転記する。アースに無い `j/k/w/v` は使わず、ジ行は `gh`、カ行は `c`、ヴは `bh`。語幹が母音で終われば第3型の主格 `-c`、子音なら第2型 `-h`（既に `-n` なら第1型系）を付け、格変化する。解析と注記で「辞書の見出しではない」と示す。普通名詞の未登録は、規則ベースでは原文の語を残す。エージェント経路では辞書の類義語へ寄せる。

## アース転写とグリフ

保証するのは「辞書見出しとフォントが、Commons 字母表のラベルと同じラテン字を指す」ことである。Wikipedia 本文が触れる au/o・p/eu の音価論争には踏み込まず、ラベル付き画像の 4×7 順を正とする。字形の載せ替えはしない。

- 辞書は Wikipedia 転写（`ai` `au` `eu` は 2 字、`é ï œ ü ÿ` は 1 字）。フォント入力だけ `to_ath_keys` で `A` `I` `E` にする。見出しに素の `A` `I` `E` は出さない。
- 取り込みと lookup は `fold_fan_romanization`（ブラウザは `foldFanRomanization`）でファン資料の代用を畳む。語中 `oe`→`œ`、`e'`→`é`、`k/j/v/w/q/x`→`c/gh/bh/u/c/cs`。語末 `oe` と主題 `F'a` は畳まない。
- 数字 0–9 は字体用で辞書見出しには出ない。ハイフンは接辞表記である。
- 詳細と資料ごとの例はリポジトリ根 README の「転写とグリフの留意点」を参照する。

日本語の部分一致 lookup は、CJK / 仮名クエリでは行わない。`ジント` が `サイ・ジント様` に吸われるのを避けるためである。

## サーバエージェント（本線の生成経路）

クライアント単発の限界は、API キーがブラウザに出ること、ツール往復を GitHub Pages から安定して回せないこと、である。エージェントは `python -m baronh serve` の `POST /api/translate` で動かす。生成 AI が無ければ 503 で止める。規則ベースへはフォールバックしない。

1. 原文トークンを辞書一致・類義語で寄せ、足りない語だけ `baronh/vectordb.py` のハッシュ n-gram 索引（512 次元、余弦類似度、閾値 0.42）で検索する。弱いベクトル類似はプロンプトにもツールにも載せない。Pinecone 等の外部 DB や埋め込み API は使わない。
2. システムプロンプトに `grammar_context()` の文法全文を載せる。規則ベースの下訳は渡さない。
3. モデルが `search_lexicon` / `find_synonyms` / `lookup_lexicon` / `transcribe_name` を使うときは `queries` / `names` にまとめて **1 往復**する。`search_lexicon` は一致と類義語を優先する。ツール実行後は `tool_choice=none` で訳文へ進む。1 語ずつの連続呼び出しは切る。文の組み立てはモデル。
4. 生成したアーヴ語を辞書語形と照合する。動詞語尾・態接辞・連語の部分形は造語とみなさない。造語なら書き直す。なお残っても規則下訳には戻さない。

例: 「光」→ ベクトル検索と類義語で `sairiac`「輝くもの」。「光」⊂「凝集光銃」のような複合語へは結ばない（長い語の 1 文字 n-gram は索引しない）。語釈から分けた補足 (`notes`) は厳密 lookup のキーにはしないが、ベクトル文書には載せて参考ヒットにする（「ラクファカール」→ `lacmhacarh` に加え、故郷 `murrautec` の用法注。「並列」→ `le` / `lo`「と」の用法注）。

GitHub Pages の静的ホストはエージェントを実行しない。翻訳ページは同一オリジンの `/api/translate` へ POST する（応答があるときだけエンジン選択肢に出る）。載せ方は [DEPLOY.md](DEPLOY.md)。

## 生成 AI（ブラウザ経路）

サーバエージェントと同じハーネスを、ページ内で組む。規則下訳は渡さない。文法は `grammarContext()` をシステムプロンプトに全文載せる。辞書は `web/js/vectordb.js` の Flat ベクトル DB で検索する。行列は GitHub Actions が `python -m baronh export-web` で blake2b 埋め込みを書き出した `vectors.bin` / `vectors.json` であり、ページ読み込み時には組まない。クエリとユーザー追加辞書だけ実行時に embed する。

### なぜ EdgeVec / USearch / Orama をバンドルしないか

調べた JS/WASM ベクトル DB:

- **EdgeVec / VantaDB / TalaDB**: ブラウザ向け WASM + HNSW。npm と `.wasm` 配布が要る。GitHub Pages のこのサイトにはバンドラが無い。
- **USearch WASM**: 作者が「ブラウザの数千件には向かない。近似検索は大規模向け」と述べている（[issue #191](https://github.com/unum-cloud/USearch/issues/191)）。
- **Voy / Orama**: 同様にバンドルか CDN が要る。埋め込みモデルは別途。

辞書は約 2400 × 512 次元である。完全な余弦類似度の Flat 索引で足り、HNSW の近似は要らない。埋め込みはハッシュ n-gram（blake2b、サーバと同じ）。索引構築は GitHub Actions の `export-web` が行い、ブラウザは `vectors.bin` を読む。外部のベクトル DB や埋め込み API は使わない。

### 呼び出しの流れ

1. 原文トークンを辞書一致・類義語で寄せ、足りない語だけベクトル索引で検索する。弱い類似は載せない。文法全文をシステムプロンプトへ載せる。規則下訳は渡さない。
2. モデルが `search_lexicon` / `find_synonyms` / `lookup_lexicon` / `transcribe_name` を使うときは `queries` / `names` にまとめて **1 往復**する。`search_lexicon` は一致と類義語を優先する。ツール実行後は `tool_choice=none` で訳文へ進む。
3. 生成したアーヴ語を辞書語形と照合する。動詞語尾・態接辞・連語の部分形は造語とみなさない。造語なら再生成する。規則下訳には戻さない。
4. Ath キーと仮名読みは生成文からローカルで再計算する。

### 長文とチャットセッション

ブラウザ経路の HAR では、ツール結果の直後のユーザー発話が「訳文だけ」になり原文が埋もれること、語形の書き直しがツール履歴を捨てて新規セッションになること、`max_rounds=3` で途中終了すると空文字になることが重なり、複数文が要約されていた。

対策:

1. 原文を句点・段落で単位に分け、2 単位以上なら `[1]` `[2]` … を付けて渡す。要約禁止を明示する。訳文側の番号は最終出力で外す。
2. ツール実行後の催促は原文を再掲する。最後のユーザー発話から原文が見えるようにする。
3. ツール往復・未訳の追記・造語の書き直しは同じ `messages` を継続する。書き直しで検索結果を捨てない。
4. 訳が単位数より短いときは、同一セッションで未訳番号だけを追記させる（最大 2 回）。
5. 往復上限に達しても、最後に得た本文があれば空にしない。`max_tokens` は原文長に応じて載せる。

短文（1 単位）の経路は従来どおりツール 1 往復のあと訳文へ進む。


### 残すファジー / 捨てるファジー

生成 AI の誤字耐性（原文を読んで意図を補う力）は捨てない。捨てるのは、意味が近そうな別語を広く拾う検索である。

| 残す | 捨てる |
|---|---|
| 原文をプロンプトに載せる（モデルが誤字を読める） | 外部ベクトル DB・埋め込み API |
| ひらがな/カタカナ、ヴ/ブ、長音、NFKC の畳み込み（`アーブ` / `あーヴ` → `abh`） | 日本語の部分一致（`ジント` ⊂ `サイ・ジント様`） |
| ラテン綴りの編集距離 1 かつ折りたたみ後 4 文字以上（`usare` → `usere`） | 日本語同士の 1 文字差（`ジントは` と `ジント様` を結ぶ） |
| ます/する など活用語尾を剥がした語釈照合 | 下訳トークンに対するタイポ照合 |
| 辞書に近い表記ゆれは、発音転記より辞書見出しを優先するよう注記する | 漢字の当て字（`わかります` と `分かります`）の自動同一視 |
| 未登録の普通名詞を、辞書語釈の短い類義語へ寄せる（エージェント） | 複合語への部分一致（`光` ⊂ `凝集光銃`） |

畳み込みと 1 文字差は「同じ語の表記ゆれ」向けである。意味の近い別語を探す処理ではない。

漢字の当て字は検索では見ない。そこは原文を読んだモデル側に任せ、見つかった見出しだけで訳させる。

### プロンプトに載せるもの / 載せないもの

載せる（エージェント）: 文法コンテキスト全文、数件の例示、ベクトル検索の上位、トークン注記。規則下訳は載せない。

載せない: 辞書全文、文法の書籍相当、外部ベクトル DB。

### 生成後の検証

目標言語が baronh のとき、生成文を語形インデックス（`FormIndex`）で照合する。

- 後置詞 `a` `sa` や `F'a` などは閉集合として許可する。
- 規則側が発音転記した固有名詞の語形は許可する。
- 原文のまま残した CJK は許可する（造語せず残す方針）。
- それ以外のラテン語で辞書語形に無いものは造語とみなす。

造語があれば一度書き直しを求め、改善すればそれを採用する。エージェント経路では規則下訳に戻さない。検証は「辞書にある語形か」であり、「関連辞書に載った語だけか」ではない。モデルが原文から正しく `abh` を思い出して `bale` と書けば通る。

### 音声合成

翻訳の Chat Completions は音声を返さない。読み上げは別呼び出しである。

アーヴ語は先にローカルで仮名読みにする。クラウド TTS はアーヴ語の読みを知らないため、ローマ字のまま渡さない。エンドポイントは `{base}/audio/speech`。未対応なら espeak-ng または `speechSynthesis`（ja-JP）に戻る。Web で TTS モデル欄を空にするとクラウド TTS は呼ばない。

### 互換 API

既定ベース URL は `https://api.openai.com/v1`。ホストだけ書くと `/v1` を付ける。LM Studio / vLLM / LiteLLM / Ollama の OpenAI 互換口など、Chat Completions と同じ形なら使える。

- CLI: `--api-base` / `--api-key` / `--model` / `--tts-model`
- 環境変数: `OPENAI_BASE_URL` または `OPENAI_API_BASE`、キーは `OPENAI_API_KEY`
- Web: `localStorage`（`ath-translate.openai-base` など）

`api.openai.com` 以外ではキー空でも `Bearer no-key` を送る（ローカル互換向け）。チャットモデルと TTS モデルは別指定である。多くのローカル互換は `/audio/speech` を持たない。

## 制約と既知の限界

- 公式辞書が無い。未登録の普通名詞は造語しない。エージェントはベクトル検索と類義語へ寄せるが、ヒットも無ければモデルが原文の語を残し得る。品質の上限は辞書の被覆で決まる。
- 二次資料の語釈は編者の再構成であり、森岡浩之氏は関知していない。
- 小さいローカルモデルはツールを呼ばないことがある。ツール非対応なら単発に落とす。規則下訳は渡していないので、なぞる下訳も無い。
- 生成エンジンでも解析ハイライトは、ツールが記録した類義語・発音転記である。最終訳の全語と一致しないことがある。
- 簡易ベクトル索引を足しても、辞書に無い概念は埋まらない。効くのは辞書の拡充と、照合の精度である。
- エージェントは生成 AI が必須。キーも互換 URL も無ければ 503 / 終了コード 2。

## 設定を変えても変わらないこと

次は実装の前提であり、API ベース URL やモデル名では変わらない。

- 辞書全文をプロンプトに載せない。
- 日本語 CJK の部分一致 lookup をしない。
- 翻訳と TTS を同じ HTTP 呼び出しにまとめない。
- アーヴ語 TTS の入力は仮名読みである。
- 固有名詞を類義語検索にかけない。
- エージェントの本体は Python であり、クラウド製品は実行場所とモデル口に過ぎない。
